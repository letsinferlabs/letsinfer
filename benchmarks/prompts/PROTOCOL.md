# Let's Infer canonical code/prose prompt protocol

`letsinfer-code-prose-v1` defines two engine-neutral domains that a runtime may
select for standard context and concurrency cells. Core owns the templates,
generator, fixed seeds, and stream ordering. A runtime declares only supported
domains, context tiers, concurrencies, execution policy, request settings, and
its exact tokenizer/render identity.
`runtime.json.benchmark` selects the suite and requires an exact tokenizer-count capability;
it does not own or alter the canonical prompt bytes.

The generated bytes for a given suite, context, domain, and stream are
identical on every model. The runtime tokenizer counts the finished request but
never resizes it. Evidence records the exact per-stream counts, so tokenizer
differences remain visible without compromising apples-to-apples prompt bytes.

- `code.md` asks for a bounded Python implementation against the canonical
  event ledger.
- `prose.md` asks for a bounded executive brief against the same ledger shape.
- C1 uses canonical stream 1; C2 uses streams 1–2; C4 uses streams 1–4; C8
  uses streams 1–8. Higher concurrency follows the same prefix rule.

Materialization rules:

1. Use the exact suite and generator version named by core.
2. Derive ledger bytes only from the suite, context, and stream identity.
3. Never use a tokenizer, timestamp, hostname, entropy, or private text to
   generate or alter prompt bytes.
4. Count the complete rendered request with the runtime adapter and record one
   positive `actual_prompt_tokens` value per stream.
5. Record the ordered per-cell prompt-set SHA-256 and the complete generated
   set, plan, templates, generator, runtime contract, tokenizer, and render
   identities in evidence.
6. Reject a cell whose actual prompt plus requested output exceeds the
   runtime's qualified context instead of shortening the prompt.
7. Obey the benchmark contract's execution policy. Generator v2/schema 2 runs
   every domain/cell with a fresh process and empty prefix store. Generator
   v3/schema 3 runs every selected cell exactly once in deterministic ascending
   concurrency/context order on one fresh matrix process/store and retains
   prefix state between cells.

Generated prompt files are ignored evidence. They are never committed to core
or packaged in a runtime.
Never commit or package materialized prompts.
